# 漫剧投放账号效能诊断项目设计规格

日期：2026-08-07
状态：A 方案已由用户确认

## 1. 目标与受众

本项目把一份 2026 年 7 月、551 个匿名漫剧投放账号、8 个匿名品牌、22 个字段的账号月度数据，整理成可公开展示、可本地复现、可部署到 GitHub Pages 的数据运营作品集。主要受众是字节跳动数据分析、经营分析、数据策略和数据运营岗位的招聘人员与面试官；次要受众是第一次学习 SQL、Python、Power BI 和 GitHub 的项目作者本人。

项目证明的是业务理解、数据质量意识、加权指标口径、可复现分析、可视化表达和行动分层能力，不声称该项目已在公司正式上线，也不声称策略已带来 ROI 提升或工时节省。

## 2. 数据边界与隐私

- 唯一业务数据源：`掌玩实习项目_漫剧投放数据_深度脱敏版.xlsx` 的 `脱敏数据` 工作表。
- 唯一业务口径来源：`漫剧投放账号效能诊断与预算分层管理项目工作手册.docx`。
- 数据粒度固定为“账号 x 月”，不能生成日/周趋势、素材归因、用户留存、LTV 或因果结论。
- 公开仓库可以包含深度脱敏版数据及其派生文件，但不得包含原始品牌、原始账号、客户隐私、缩放系数或凭据。
- 网页只使用派生后的匿名字段：匿名账号、匿名品牌、展示、点击、播放、消耗、24 小时混合变现、重算指标、样本标记和行动标签；移除客户字段。
- 所有文本明确披露数据经过匿名替换和同比例缩放，绝对金额只能用于本数据集内部相对比较。

## 3. 业务问题与指标模型

项目回答五个问题：品牌规模与效率是否匹配；预算是否集中；哪些高消耗账号回收不足；哪些有效账号可小步扩量；哪些账号样本不足。

核心指标全部从基础量重新计算：

- 加权 CTR = 总点击 / 总展示。
- 加权 CPC = 总消耗 / 总点击。
- 加权 CPM = 总消耗 x 1000 / 总展示。
- 加权播放率 = 总播放 / 总展示。
- 加权播放成本 = 总消耗 / 总播放。
- 24 小时混合 ROI = 24 小时混合变现 / 总消耗。
- 品牌指标禁止对账号级比率做简单平均。

样本门槛固定为消耗 50，ROI 参考线固定为 1.0。达到门槛的账号以消耗第 75 百分位为高消耗边界，形成五类行动标签：核心扩量候选、高消耗重点优化、小步扩量观察、低效清理候选、数据不足/低量池。ROI=1 只表示本口径下变现金额覆盖投放消耗，不等于公司盈利。

## 4. 技术架构

### 4.1 可复现数据管道

`src/manga_ad_analysis/` 提供独立模块：字段映射与加载、质量检查、安全除法与加权聚合、Pareto、分层、洞察和导出。`scripts/run_pipeline.py` 是唯一批处理入口，读取 XLSX 并生成 CSV、JSON、图片和验证摘要。所有新增业务函数先有失败测试，再实现。

### 4.2 SQL

MySQL 8 脚本包含建库建表、质量检查、品牌加权汇总、Pareto 和账号分层。SQL 与 Python 使用同一字段名、门槛和指标公式。仓库附带导入说明与对账查询；由于交付环境不保证存在 MySQL 服务，自动验收以 SQL 解析、静态约束和 Python 结果对账为主，实操手册提供 MySQL Workbench 的人工运行步骤。

### 4.3 Notebook

两个已执行 Notebook 分别承担数据质量和账号诊断。它们调用项目模块，不复制另一套业务逻辑；结构为 tl;dr、Context & Methods、Data、Results、Takeaways，并保留有界输出与图表。

### 4.4 GitHub Pages 看板

看板使用 React + Vite，部署时从 `web/public/data/dashboard.json` 读取预计算匿名数据，不依赖后端或数据库。三个页签与 Power BI 施工包一致：经营总览、品牌对标、账号行动池。全局筛选器为品牌、行动标签和样本状态；筛选后 KPI、图表和表格联动。桌面端优先，同时支持窄屏浏览。

GitHub Actions 在每次推送到默认分支时安装依赖、构建 `web/dist` 并发布 GitHub Pages。Vite 使用相对资源基址，保证仓库子路径部署可用。

### 4.5 Power BI 施工包

不伪造 `.pbix`。`powerbi/` 提供可直接复制的 DAX、Power Query M、主题 JSON、星型模型说明、三页布局说明、视觉对象字段映射、格式规则与逐项验收清单。用户在 Windows Power BI Desktop 中按实操手册生成 `.pbix`。

### 4.6 报告与表格

仓库包含一个面向业务读者的 `analysis_report.pdf`，按“答案 -> 证据 -> 动作 -> 验证 -> 边界”组织；包含品牌比较、Pareto、行动分层和相关性图。`data_dictionary.xlsx` 包含字段字典、指标口径、数据源评估、质量检查、行动规则五个工作表，便于学习和审计。

## 5. 交付结构

仓库包含 README、公开数据、SQL、Python 包、两个 Notebook、分析输出、图表、React 看板、Power BI 施工包、分析报告、数据字典、面试话术、测试、GitHub Pages 工作流和忽略规则。仓库外另行交付：完整实操手册 DOCX、字节数据岗位校招简历 DOCX/PDF、完整项目 ZIP。

## 6. 简历边界

简历姓名使用已核实的“蔡健明”。教育信息仅使用已核实的浙江财经大学、经济统计学、GPA 3.26；未检索到的手机号、邮箱和教育起止时间显示为醒目的用户填写字段。掌玩经历如实写素材上传、B 站推送、品牌产品投放基建和计划搭建，以及主动使用 Excel、R、Python 和自建前端对历史周数据进行三次复盘并向带教展示。宁德新能源 PMC 经历、艺术团副团长、英语六级和省级艺术节金奖仅使用既有简历中可核实的信息。

个人分析项目与岗位职责分栏呈现，明确为基于实习场景主动发起；不写“主导公司数据平台”“上线推动 ROI 提升”等无证据结果。

## 7. 错误处理与可解释性

- 缺少必需工作表或字段时立即失败并列出缺失项。
- 主键重复、负值、点击大于展示、播放大于展示作为质量失败；零分母作为可解释警告并安全返回空值或 0（按展示场景定义）。
- 输出目录可重复生成；运行前只覆盖明确的派生文件，不删除用户文件。
- 洞察生成使用已验证数字和限定性语言；相关性只写关联与待验证假设。
- 看板加载失败时显示可操作错误信息和本地复现命令，不显示空白页。
