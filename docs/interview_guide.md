# 面试讲解指南

## 30 秒版本

我基于实习场景中的一份深度脱敏账号月度数据，主动做了一个可复现的投放效能诊断项目。核心不是做复杂模型，而是先锁定账号月粒度和加权指标口径，发现源“播放成本”公式方向相反，再用 Python、MySQL、Excel 数据字典、React 看板和 Power BI 施工包形成同口径交付。最后以消耗门槛、有效账号消耗 P75 和 ROI 参考线把 551 个账号分成五类行动池，并明确单月数据只能给出优先级，不能证明因果或收益。

## 3 分钟版本

### 1. 背景与问题

实习工作以素材上传、B 站推送和广告系统品牌/产品基建为主。我在完成日常工作的同时，主动复盘了三次历史周数据，并进一步把一份深度脱敏账号数据整理成个人作品集。问题是：品牌规模与回收是否匹配、预算是否过度集中、哪些账号应该扩量或优化、哪些账号样本不足。

### 2. 先做口径而不是先画图

数据是 2026 年 7 月的 551 个账号、8 个品牌、22 个字段。质量检查发现没有缺失和重复，但源“播放成本”实际等于播放量除以消耗，方向与通常成本相反。我保留源字段用于审计，分析统一重算为消耗除以播放量。品牌 CTR、CPC、播放率与 ROI 都采用先汇总分子分母再相除，避免平均比率偏差。

### 3. 分层与结果

我把消耗 50 设为稳定分析门槛，283 个有效账号覆盖 99.43% 消耗；再用有效账号消耗 P75=735.80 区分高消耗，ROI=1 作为回收参考线。得到 62 个核心扩量候选、9 个高消耗重点优化、137 个小步扩量观察、75 个低效清理候选、268 个低量池。Top 10% 账号贡献 64.74% 消耗，说明管理动作应先集中在头部。

### 4. 技术与交付

Python 包是唯一业务逻辑来源，输出 CSV、JSON、图表和执行回执；MySQL 8 脚本复刻质量、品牌、Pareto 和分层；两个 Notebook 保留可复查过程；React/Vite 看板可发布 GitHub Pages；Power BI 提供 DAX、M、主题和验收清单，不伪造 PBIX。测试不仅检查代码运行，还对账账号数、消耗、分层、公开字段和移动端交互。

### 5. 边界与下一步

这是个人分析项目，不是公司上线成果。数据单月且经过缩放，所以我不声称趋势、因果、利润或 ROI 提升。若获得日级、素材和计划数据，我会预先定义观察窗与止损线，跟踪边际 ROI，并用小规模对照验证扩量策略。

## 高频追问

### 为什么不能平均账号 ROI？

不同账号消耗量级差异很大。简单平均会让低消耗账号和高消耗账号获得相同权重；正确做法是总变现除以总消耗。这个项目的品牌和全局指标都使用加权口径。

### 为什么门槛是 50？

它来自项目口径，用于隔离几乎无消耗的高噪声账号。更重要的是我展示了门槛影响：283 个账号覆盖 99.43% 消耗。线上应用前应结合历史波动和业务容忍度做敏感性分析，而不是把 50 当永恒规则。

### 为什么用 P75？

P75 是透明、易复现的规模分层，不假设正态分布。它帮助把高消耗低回收的 9 个账号从普通低效账号中单独提出来，以匹配管理优先级；不是预测模型。

### ROI 大于 1 为什么不一定赚钱？

这里只有 24H 混合变现与投放消耗，没有内容成本、渠道分成、人力、税费、长周期退款等信息。因此 ROI=1 只是当前口径的回收线，不是公司利润线。

### 相关性结论是什么？

有效样本中单一前链路指标和 ROI 的 Spearman 关联都很弱，说明不能仅凭 CTR 高就推断回收好。重算播放成本与 ROI 为 -0.128，也只能作为排查顺序，不能解释原因。

### 你在公司实际做了什么？

实际职责是日常视频上传、B 站推送、广告系统品牌/产品基建和计划搭建。我额外用 Excel、基础 R/Python 和自建前端做过三次历史周数据复盘并向带教展示。当前完整项目是在脱敏数据上继续主动完成的个人作品集，未声称在公司正式上线。

### 没有 PBIX 怎么证明 Power BI？

我提供的是可审计施工包：数据模型、Power Query、DAX、主题、三页字段映射和验收基线。面试时可在 Windows Power BI Desktop 按步骤构建并现场解释每个度量；简历只写“设计模型与 DAX/构建指南”，不会写已交付 PBIX。

## STAR 表达提示

- S：账号多、规模差异大，日常报表难直接对应动作。
- T：建立统一口径、识别高优先级账号，并做可复现作品集。
- A：审计字段 → 重算指标 → 加权聚合 → Pareto → 五类分层 → 多端交付与测试。
- R：交付 551 个账号的完整行动池和可追溯分析资产。结果只描述交付与发现，不编造业务提升。
